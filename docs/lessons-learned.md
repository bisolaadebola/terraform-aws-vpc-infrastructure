# Lessons Learned

## Terraform & Infrastructure as Code

This project strengthened my understanding of using **Terraform to provision AWS infrastructure as code** rather than creating resources manually through the AWS Console.

Key lessons included:

* Writing reusable Terraform configurations.
* Understanding Terraform providers, resources, variables, and outputs.
* Using Terraform state to track deployed infrastructure.
* Following the workflow: `init → validate → plan → apply`.
* Managing infrastructure changes through code.

## AWS Networking

Building the VPC infrastructure improved my understanding of AWS networking, including:

* VPC and CIDR addressing
* Public and private subnets
* Availability Zones
* Internet Gateway
* NAT Gateways
* Route tables and subnet associations
* Security groups

I gained a better understanding of how public and private resources communicate within an AWS environment.

## Infrastructure Design

Deploying resources across multiple Availability Zones reinforced the importance of:

* High availability
* Network segmentation
* Secure resource communication
* Scalable infrastructure design

## Troubleshooting

The project also strengthened my ability to troubleshoot Terraform and AWS configuration issues by:

* Reviewing Terraform plans before applying changes.
* Checking Terraform state.
* Verifying AWS resources through the Console.
* Identifying incorrect resource dependencies and configurations.
* Testing connectivity between infrastructure components.

## Key Takeaway

The biggest lesson from this project was understanding how **Infrastructure as Code makes cloud infrastructure repeatable, consistent, and easier to manage**.

This project gave me practical experience connecting **Terraform, AWS networking, security, and compute infrastructure** into a single deployable environment.
